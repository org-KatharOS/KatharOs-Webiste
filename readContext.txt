
What is Katharos? 🧹
Katharos is a secure data-sanitization solution built as a modern cross-platform desktop application using:
•	Electron framework with React + TypeScript for a responsive, user-friendly interface
•	WebSocket-based real-time communication for live progress updates and drive management
•	Comprehensive safety measures with multiple confirmation modals and keyboard navigation
•	Local certificate storage with email delivery and tamper-proof signing
It’s designed to help individuals, businesses and recyclers safely dispose or resale IT assets without fear of data recovery, featuring modern UI/UX with dark theme and accessibility support.

Why Katharos? — The Problem It Solves ♻️
•	Millions of devices are hoarded because users fear data breaches from discarded drives.
•	Existing tools are either complex, limited to experts, or lack tamper-proof certificates.

High-level Flow — How Katharos Works (User view) 🔁
1.	Launch Desktop App: User launches the Katharos Electron application on Windows, macOS, or Linux.
2.	WebSocket Connection: App establishes real-time connection to backend service at localhost:8080.
3.	Scan Drives: User clicks "Scan Drives →" to enumerate all connected storage devices.
4.	Select Drive: Interactive data table displays drives with keyboard/mouse navigation support.
5.	Configure Wipe: Modal interface for selecting wipe method, passes, and certificate options.
6.	Safety Confirmations: Sequential warning and confirmation modals prevent accidental data loss.
7.	Real-time Wiping: Live progress updates via WebSocket with animated progress bar and status.
8.	Certificate Generation: Signed certificates stored at /tmp/katharos/certificates with optional email delivery.
9.	Completion: Success screen with certificate location and email confirmation.

Technical Approach & Architecture ⚙️
Core components
•	Electron Desktop Application — Cross-platform desktop app built with Electron 30.0.1, React 18.2.0, and TypeScript.
•	WebSocket Communication — Real-time communication between frontend and backend services via ws library.
•	Wipe Engine — Backend service with open-source tools: nwipe, shred, dd, hdparm, nvme-cli.

•	Optional Anchoring — IPFS / OpenTimestamps / (optional) blockchain tx for immutable proof.

How Certificates Work — Tamper-proofing explained 🧾🔐
1.	Log capture: Raw wipe output and verification outputs are captured into wipe_log.txt.
2.	Hash & sign: log_hash = SHA-256(wipe_log) stored in certificate.json. The JSON is signed with ECDSA (private key).
3.	Timestamp/anchor (optional): Use RFC3161 TSA or OpenTimestamps / IPFS anchoring to provide tamper-evident proof of time.
4.	PDF: Human-readable summary (device metadata, method, timestamps, signature) + QR linking to verification URL.
5.	Verification: Third party verifies signature against published public key and checks timestamp/anchor.
Why this is tamper-proof: Changing certificate JSON will break the signature; certificate anchored externally adds a public immutable record.

Device-specific Wiping & Verification Logic 🔎
HDD (rotational)
•	Method: random overwrite or multi-pass overwrite.
•	Verify: sample read-back and hash sectors; verify tool exit codes.
SATA SSD
•	Method: ATA Secure Erase (firmware command) OR cryptographic key destruction (if encrypted).
•	Verify: firmware success codes, SMART/log checks (readback unreliable due to wear leveling).
NVMe
•	Method: NVMe sanitize / format commands via nvme-cli.
•	Verify: sanitize status & controller logs.
Android/Internal Phone
•	Method: factory reset + key discard OR advanced vendor/provisioned wipe for rooted devices.
•	Note: For phones, best practice is encryption + reset.
Important: For SSDs, verification is based on controller acknowledgement — we explicitly state this limitation in the certificate.

Security & Operational Best Practices 🔒
•	Never embed private keys in client builds. Use KMS/HSM for signing in production.
•	Always show limitations clearly (SSD overwrite vs secure erase differences).
•	Audit logs: append-only server storage for issued certs; provide operator ID, app version.
•	Key rotation & revocation: publish key fingerprints & revocation list for compromised keys.
•	No user data collection: do not upload file contents — only logs & device metadata (with user consent).
________________________________________
Testing & Validation (how we prove effectiveness) 🔬
•	Recovery tests: run testdisk, photorec, foremost, bulk_extractor on wiped drives — expected no recoverable data (or only high-entropy noise).
•	Entropy checks: sample sectors and run entropy tools to show randomness.
•	SSD verification: validate controller sanitize/secure-erase status codes + vendor tool outputs.
•	Edge case tests: USB-SATA bridge limitations, frozen drives, bad sectors (recommend physical destruction).
________________________________________
Limitations & Disclaimers ⚠️
•	SSD cell-level proof impossible outside vendor/firmware acknowledgement (wear-leveling). Certificates will state this clearly.
•	USB bridges may prevent firmware-level ATA commands — may require direct SATA connection.
•	Physical failures: failing drives may not be sanitizable; recommend physical destruction.
•	Phone OEM variations: Android/device differences may limit actions; suggest factory reset where appropriate.

FAQs — Quick Answers 📝
Q: How do I install and run Katharos?
A: Katharos is an Electron desktop application. Download and install the package for your operating system (Windows, macOS, Linux). The app will establish a WebSocket connection to the backend service automatically at localhost:8080.
Q: Can I wipe my system drive?
A: The current desktop version is designed for external drives. For system drives, you would need to boot from external media or use the drive on another system.
Q: Is the certificate proof absolute?
A: Certificates prove the app ran an approved method and that the result/logs were signed. For HDDs proof is stronger (read-back verification). For SSDs we rely on controller sanitize acknowledgement; the certificate explains that limitation.
Q: Will Katharos upload any personal files?
A: No. It only collects device metadata and wipe/log hashes for the certificate — not user file contents. All certificates are stored locally at /tmp/katharos/certificates.
Q: What happens if the wiping process is interrupted?
A: The application includes safety mechanisms and progress tracking via WebSocket. You can monitor the process in real-time and the system handles interruptions gracefully with proper error handling.
